# 规范 3.1 验证记录（2026-11-13）

- XML 主包与模块仓库里图标包工具生成的示例库逐字节相同。它只作为图标包作者的参考发布在本仓库，模块本身不内置这个库。
- 生成器按 214 角色快照重新生成：原有 189 个角色的母版与上一版逐字节相同（只差换行符），新增 25 个角色（音量面板 `slider.panel_*` 与单张自动亮度 `slider.brightness.auto`）的母版各一份 XML 与 PNG。
- 逐个核对 XML 主包与母版：83 个不写 `fit` 的图标、7 个带转场只标记画布的图标（深色模式、手电筒、自动旋转的各状态）与母版逐字节相同；其余 124 个只多一个 `<group>` 变换（`<vector>` 的宽高与 viewport 改为系统画布），其他内容相同；3 个转场 JSON 相同。
- `python tools/validate_pack.py` 两个包都通过；`python tools/check_validator.py` 88 例通过，其中 65 个畸形包全部拒绝（新增：`fit` 为 `canvas`/`visible` 时通过，未知取值和写在包顶层时拒绝）。
- `manifest.schema.json`（JSON Schema 2020-12）自身与两份清单通过，顶层写 `fit` 时不通过。

## 检查工具

`python tools/check_spec.py dist/c17-rounded-27.zip`：没有缺 `fit`、画布比例、超出画布或状态不一致的问题；2 个大小提示：

- `slider.panel_media.mute`：面积 0.53，系统 0.76（小 30%）；
- `tile.dark.on`：面积 0.59，系统 0.91（小 35%）。这是带转场、只标记画布的图标，图形保持与动画末帧一致。

与模块仓库里用模块自己解码器的检查工具对比同一个包：214 个图标列出的问题逐个相同；显示大小的比例中位数相差 0.3%，最大相差 7.7%（`wifi.1`，图形很小，各档只比最满一档，不单独判断）。工具把 XML 的几何范围每边放宽半个像素（按 192 px 解码），对应模块按 Alpha > 0 的像素取范围。

PNG 备用包（3.0 旧规则）按 3.1 检查有 131 个缺 `fit`、49 个显示大小超出 25%，说明不写 `fit` 时显示大小与系统图标不一致。

另用故意做坏的小包核对：画布比例不符、`<group>` 平移后超出画布、缺 `fit`、clip-path 裁切、同一图标各状态缩放不同、带弧线和二次曲线的路径都按预期列出（该测试包未收进仓库）。

## 兼容性

- 公开发布的模块 2.1.0（code293）读取清单时，每个图标只允许 `source`、`render`、`sha256`，含 `fit` 的图标包会被整个拒绝。`fit` 从 2.1.1_beta.009（code302）起识别。
- 新增的 25 个角色从 2.1.1_beta.002（code295）起登记；更早的版本把 `slider.brightness.auto` 当作已登记目标的非法状态，拒绝整包。
- 本仓库的 schema 与预检工具还不支持模块已有的 `colorPresets` 和 `nativeAnimations` 字段。
